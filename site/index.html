What this measures

Verifiability and supply-chain stability — not exploitability. Every input is public metadata: the official MCP Registry, npm, PyPI, and public GitHub repo status. Nothing here runs, connects to, or tests anyone's server. A low grade means "nobody outside the publisher can check what this thing does" — never a claim that it is malicious.

Honest caveats — read before quoting us

1. Description drift is mostly benign. 21.6% of sampled npm packages changed their description between the last two releases. We read the examples: nearly all are marketing copy edits and feature announcements, not rug-pulls. We publish it as a monitoring signal only.
2. "Description differs between registry and npm" is noise, not a signal. It fires on 87.4% of packages, so it carries no information — we score it at 0 penalty.
3. Namespaces matter. GitHub-verified io.github.* servers declare source 92.3% of the time; unverified namespaces only 49.2%. The "no source" problem is concentrated in unverified namespaces.
4. Point-in-time. Scores describe the moment of the scan.
